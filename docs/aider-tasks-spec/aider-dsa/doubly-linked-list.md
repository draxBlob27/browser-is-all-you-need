# Doubly-Linked-List Family Remediation Specification

## Scope and immutable inputs

This report controls local remediation of the 20 generated roots at
`.w8-biayn/data/aider-tasks/aider-dsa/doubly-linked-list/`. That legacy tree is
audit input and is not modified. The owner is
`src/w8_biayn/integrations/moonlight_doubly_linked_list_aider_tasks.py`; fresh
artifacts are generated only under
`.w8-biayn/data/aider-tasks-reverify/aider-dsa/doubly-linked-list/`.

The selected workflow prompt is
`docs/aider-tasks-spec/prompts/remediate-family-reverify.md`, with user inputs
`FAMILY_NAME=doubly-linked-list` and `FAMILY_TYPE=aider-dsa`. The official
Aider C++ `linked-list` root is a permanent holdout. This work is local family
remediation only: no dataset row, split, token/mask ledger, export, training
run, or uplift claim is authorized.

## Legacy audit

The audit found 20 roots. Nineteen were generated by one parameterized
`positive unique integer ID + add/remove/move + forward/reverse snapshot`
template. Their public names and verbs differed, but their authoritative state,
implementation body, invalid-input policy, tests, and observable transitions
were the same. The generated API did not implement the domain behavior promised
by most blurbs. `dll-tab-strip` had separate older files, but lacked the
family-wide locked receipt, structural negative fixture, prompt receipt, and
semantic screen required by the current remediation policy.

### DLL-F1 — template duplication

**Severity:** major

**Scope:** every legacy root except the independently shaped tab-strip root.

**Observed evidence:** the owner rendered the same `_header`, `_reference`,
`_starter`, and `_test` functions for 19 tuple rows. Normalizing class/entity
names and method verbs made the references and tests identical.

**Why it matters:** a solution to one root transfers mechanically to the other
18; domain renaming does not supply independent learning value.

**Root cause:** task blurbs were treated as labels rather than executable
contracts.

**Remedy:** repair the lexicographically smallest independently justified
representative (`dll-book-shelf`) in place and replace the other 18 tuple roots
with new IDs, APIs, policies, implementations, and tests.

**Verification after remedy:** the owner must report 20 unique logic tags and a
normalized family Jaccard score below the fail-closed `0.60` duplicate
threshold. This stricter threshold forced redesign of both the original
range-splice/reversal collision and the cursor-history/undo collision.

**Status:** resolved in owned source; runtime re-verification is recorded in
the generated receipts.

### DLL-F2 — core contract mismatch

**Severity:** major

**Scope:** the same 19 generated roots.

**Observed evidence:** blurbs promised branch pruning, circular rotation,
selection fallback, contiguous reversal, fairness, priority, dependency, and
cursor behavior, while every reference implemented only the common generic
mutation template.

**Why it matters:** compiling examples did not establish the advertised state
transition or a real task-specific implementation.

**Root cause:** neither the generator nor focused tests bound each blurb to a
distinct API and discriminating private trace.

**Remedy:** each retained/replacement root owns a heap-allocated reciprocal
node chain and a distinct policy mechanism. A test-only link audit runs after
the task-specific trace, and the core verifier executes a
`vector_authority_fixture` rejection path.

**Verification after remedy:** `--verify-core` must report
`primary_core_objective=achieved`, reject the vector fixture with
`invariant_not_enforced`, and pass prompt/role/family checks.

**Status:** resolved in owned source; oracle status remains a separate gate.

### DLL-F3 — evidence boundary

**Severity:** moderate

**Scope:** all 20 roots.

**Observed evidence:** the legacy generator had no positive discovery receipt,
fresh ASan/UBSan count comparison, bound runtime identity, family semantic
screen, or prompt hashes.

**Why it matters:** structural inspection and a host build cannot establish
locked oracle verification or local-family completion.

**Root cause:** the legacy materializer predated the deterministic remediation
contract.

**Remedy:** generate per-root tree-bound normal/sanitizer receipts using the
explicit compiler and Unix Makefiles in the designated network-disabled image;
record unavailable prerequisites as `not_completed`.

**Verification after remedy:** `--verify` requires two positive CTest entries
in both modes for each root, equal counts, passing references, and exact runtime
identity fields.

**Status:** determined by generated oracle receipts, never inferred here.

## Structural and prompt contract

Every task declares exactly two editable files named from its root slug, two
private reference files with one-to-one suffix mapping, one visible and one
private Catch test, and content-addressed Catch support. The prompt builder is
run for every root. It must contain only documentation and the two starter
files; reference, test, metadata, CMake, support, and receipt names are rejected
if they appear.

The authoritative representation is an owned node chain with reciprocal raw
links. Output vectors are observations only. `std::list`, `std::deque`,
vector-backed authoritative order, associative containers, third-party lists,
and hard-coded traces are forbidden. The private audit checks head/tail null
boundaries, reciprocal links, cycle bounds, and equal complete traversal
counts.

## Family and benchmark screen

The screen compares normalized docs, API, reference, visible tests, and private
tests for all 20 roots. It removes comments, strings, literals, and domain nouns
while retaining API arity, control flow, link invariants, and assertions. It
also compares those signatures with every available bound official C++ holdout
under the pinned upstream checkout. Missing holdout content is
`not_completed`, not a pass. Whole-slug overlap always fails with
`benchmark_id_overlap`; semantic overlap fails with
`benchmark_content_overlap`; within-family duplication fails with
`duplicate_family`.

## Legacy audit summary

The legacy inventory contains exactly twenty roots. All have structurally
plausible task-shaped files and task-named editable headers/sources, but the
advertised domain mechanisms are absent. Every reference performs the same
centered odd-span loop; the only substantive family variation is whether a
single parity predicate is enabled. The tests likewise check the same one-row,
three-row, symmetry, width, and generic validation cases. Consequently the
primary core objective is `not_achieved` for every legacy root.

### PATTERN-PRINT-001 — Advertised mechanisms are absent

**Severity:** major

**Scope:** every legacy root

**Observed evidence:** normalized reference inspection collapses the family to
the same centered-span loop and parity toggle; no theater allocation, route,
truss, pennant, canopy union, bracket, ray occlusion, quilt ring, token layout,
trellis overlay, glyph composition, cadence, rink overlay, or brace
triangulation exists.

**Why it matters:** passing builds would train a renamed generic renderer, not
the stated capability.

**Root cause:** one superset template parameterized by nouns, marker literals,
and one boolean.

**Remedy:** repair one recoverable archway root and replace the other nineteen
with the exact mechanisms in the owning curriculum/case inventory.

**Verification after remedy:** `--verify-core` must locate each body, execute
its task-specific false substitute, and record
`primary_core_objective: achieved` only after the runtime gates pass.

**Status:** resolved and reverified by the pinned Docker receipt.

### PATTERN-PRINT-002 — Family is a semantic/template duplicate

**Severity:** major

**Scope:** every legacy root

**Observed evidence:** APIs, state, validation, control flow, tests, and output
diagnostics differ only by domain names, symbols, and the stripe predicate.

**Why it matters:** twenty renamed copies do not provide twenty independent
learning roots.

**Root cause:** inventory count was treated as diversity evidence.

**Remedy:** one `repair-in-place` disposition and nineteen `replace`
dispositions, with new task IDs and all-pairs artifact-derived screening.

**Verification after remedy:** require 190 comparisons plus the three required
adversarial clone controls.

**Status:** superseded. The earlier v3 conclusion used one aggregate overlap
per pair and did not prove the seven-dimensional hard rule. It was explicitly
withdrawn and replaced by the v4 evidence below.

### PATTERN-PRINT-003 — Negative fixtures did not establish the concepts

**Severity:** major

**Scope:** every legacy root

**Observed evidence:** legacy visible/private tests only distinguish solid from
striped centered spans; they cannot reject a renamed generic renderer.

**Why it matters:** the primary content claim lacks a deterministic
discriminator.

**Root cause:** tests were emitted from the same generic template as the
reference.

**Remedy:** emit one compilable, executed mechanism-specific false substitute
per v3 root and require exit 1 under normal and sanitizer builds.

**Verification after remedy:** three positive CTest discoveries per mode and
explicit negative execution/outcome in the Docker receipt.

**Status:** resolved and reverified: every false substitute exited 1 in both modes.

### PATTERN-PRINT-004 — Required local-family evidence was absent

**Severity:** blocker

**Scope:** every legacy root

**Observed evidence:** no parallel remedy ledger, all-pairs screen, bound
holdout screen, independently mounted tree hash, or pinned network-disabled
normal/sanitizer receipt existed.

**Why it matters:** host compilation cannot support `local_family_verified`.

**Root cause:** the legacy owner predates the deterministic remediation
contract.

**Remedy:** generator-owned remedy records/specifications, parallel
materialization, semantic screens, and snapshot-safe Docker sanity receipt.

**Verification after remedy:** focused tests, `--verify-core`, `--verify`, and
`--docker-sanity`, followed by receipt/live-tree reconciliation.

**Status:** resolved and reverified by the mounted-hash-bound Docker receipt.

### PATTERN-PRINT-005 — v3 hard-rule evidence was aggregate-only

**Severity:** blocker

**Scope:** every v3 root and the earlier `local_family_verified` claim

**Observed evidence:** `pattern-printing-family-screen-v3` recorded one
aggregate normalized overlap for each pair. It did not independently compare
public API, owned state/algorithm, mutation/selection, invalid/boundary
behavior, reference control flow, deterministic oracle, and the topic-specific
negative fixture. The focused test counted pairs and clone outcomes but did not
assert a complete seven-dimension matrix.

**Why it matters:** aggregate differences can hide a clone in one mandatory
dimension, and profile labels or raw source inequality cannot repair that gap.

**Root cause:** the v3 owner inherited a family-level similarity screen and
treated it as the skill's stricter hard-rule proof.

**Remedy:** withdraw the v3 status, derive seven independent feature sets from
the actual emitted docs/API/reference/tests/negative, compare all 190 pairs
dimension by dimension, store per-root fingerprints and pair evidence, and
bind the resulting screen hash into the Docker receipt and every remedy record.

**Status:** resolved in v4. All 190 pairs passed all seven dimensions, and the
three coherent clone controls were rejected in all seven dimensions.

### PATTERN-PRINT-006 — strict screening exposed a semantic twin and API collisions

**Severity:** major

**Scope:** the proposed v3 replacement inventory

**Observed evidence:** the first strict run rejected
`ridge-height-silhouette` versus `warehouse-height-columns` as the same
bottom-aligned height-column renderer. It also found normalized public-API
collisions among truss/rink, lighthouse/trellis, and related report shapes.

**Why it matters:** domain renaming and diagnostic-field renaming do not create
distinct roots, even when the aggregate family score is below threshold.

**Root cause:** the initial replacement inventory was designed against the
aggregate screen rather than every mandatory dimension.

**Remedy:** replace `warehouse-height-columns` with
`warehouse-aisle-run-map`, a non-overlapping interval-placement task, and add
observable task-specific state/oracles for truss joint columns, lighthouse
occluded targets, trellis crossing coordinates, and rink zone columns/labels.

**Status:** resolved in v4 and confirmed by the seven-dimension screen plus the
fresh normal/sanitizer Docker oracle.

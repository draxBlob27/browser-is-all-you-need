# Spiral Matrix Legacy-Family Rejection Specification

## Scope

This report audits the 20 generated roots at
`.w8-biayn/data/aider-tasks/aider-text-grid-reshaping/spiral-matrix/` under the
user-selected `remediate-family-reverify.md` workflow. The legacy tree is
immutable. Re-verification evidence lives at
`.w8-biayn/data/aider-tasks-reverify/aider-text-grid-reshaping/spiral-matrix/`.

The official Aider C++ `spiral-matrix` root is a permanent holdout. The local
workflow is not dataset admission and creates no rows, split, token/mask
evidence, export, training run, or uplift claim.

## Primary core-objective conclusion

`primary_core_objective: achieved` for the historical implementation: every
reference genuinely constructs and executes an inward shrinking-rectangle
boundary walk. That conclusion does not make the roots suitable. The same
control flow, state, mutation, ordering, boundary behavior, oracle shape, and
tests are repeated across all 20 roots, with domain names, start corner,
direction, predicate, aggregate, and early-stop policy changed as constants.

## Deterministic disposition

The first matching disposition rule is official-benchmark semantic overlap or
a holdout family divided across candidates. The local roots teach ordered
inward boundary traversal from a corner—the mechanism that defines the
permanent holdout—then add blocked-cell filtering and renamed reports. Every
root is therefore `reject`. Template duplication would independently require
replacement, but it cannot weaken or override the earlier benchmark rule.

There is no independently justified representative. A rename, reversed
direction, changed start corner, changed predicate, or changed statistic is
not a remedy. This family emits zero replacement C++ roots.

## Findings

### SM-BENCHMARK-FAMILY-OVERLAP — holdout capability partitioned across candidates

**Severity:** blocker

**Scope:** every legacy root

**Observed evidence:** the official instructions require an inward clockwise
spiral from the top-left; every local contract requires successively shrinking
rectangular boundaries from a selected corner and direction. The references
implement that ordering with four shrinking bounds and the same perimeter
construction.

**Why it matters:** domain nouns and extra output fields do not create a
clean-room learning objective when the central traversal capability remains
the official holdout.

**Root cause:** curriculum design treated direction, corner, blocked cells,
predicate, and aggregate as sufficient decontamination of the holdout family.

**Remedy:** reject all 20 roots and prevent the owner from emitting candidates
under the re-verification family.

**Verification after remedy:** `--verify-core` must bind the official holdout,
find zero candidate roots, and record `benchmark_content_overlap`.

**Status:** resolved by terminal rejection

### SM-RENAMED-RING-TEMPLATE — all roots share one primary implementation

**Severity:** major

**Scope:** every unordered pair in the 20-root family

**Observed evidence:** normalizer
`spiral-matrix-rejection-v2-seven-dimension-artifacts` derives evidence from
the actual emitted documentation, public header/API, reference source, visible
test, private test, and topic-negative role. It records public API, owned
state/algorithm, mutation/selection, invalid/boundary behavior, reference
control flow, deterministic oracle, and topic-specific negative fixture for
all 190 unordered pairs. All pairs are `duplicate_family`; the absent
topic-specific negative fixture is itself shared missing evidence rather than
manufactured diversity.

**Why it matters:** 20 renamed instances do not provide 20 independent
learning capabilities.

**Root cause:** one superset `TaskSpec` and one shared reference/test renderer
parameterized the entire family.

**Remedy:** terminal rejection. A later clean-room grid curriculum, if
separately requested, must use a different family ID and independently authored
mechanisms; it cannot be presented as repaired `spiral-matrix` roots.

**Verification after remedy:** the focused test copies a real emitted root
three times, renames its files/config/domain/API, applies a constants-only
predicate mutation, and changes the selected boundary endpoint. Each clone has
a distinct tree hash and is passed through the same production `_pair_result`
screen. The measured overall overlaps are respectively `1.0`, approximately
`0.996`, and `1.0`; all three return `duplicate_family` with seven-dimension
evidence.

**Status:** resolved by terminal rejection

### SM-NONDISCRIMINATING-TESTS — tests validate policy outputs, not diversity

**Severity:** major

**Scope:** every legacy root

**Observed evidence:** the two deterministic executables cover rectangularity,
empty and narrow grids, blocked cells, first flags, and coordinate uniqueness.
They do not establish root-specific algorithms because the same renderer emits
the same operation sequence for every root.

**Why it matters:** positive tests can prove the shared implementation works
without proving that each root teaches an independent capability.

**Root cause:** policy values were treated as task mechanisms.

**Remedy:** do not add more assertions to the contaminated contract. Reject
the root before implementation/oracle admission.

**Verification after remedy:** remedy records remain terminal `rejected`; no
runtime pass may upgrade them to `implemented` or `local_family_verified`.

**Status:** resolved by terminal rejection

### SM-ORACLE-CARGO-FAILURE — historical reference fails its own tests

**Severity:** blocker

**Scope:** `spiral-cargo-inspection`

**Observed evidence:** the pinned, network-disabled Docker audit discovered
two normal and two fresh ASan/UBSan CTests. Both tests failed in both modes;
the receipt retains bounded output hashes and mode-specific statuses.

**Why it matters:** a reference that fails its own deterministic grader cannot
be oracle-verified even if structural and semantic screens were otherwise
clean.

**Root cause:** the shared visible/private fixture expects an early-stop visit
count that does not match the root's configured corner/direction/predicate
trace.

**Remedy:** no generated-file repair is allowed after the earlier terminal
benchmark rejection. Record the failure on the remedy and keep the root
rejected.

**Verification after remedy:** the historical Docker receipt must continue to
report positive equal discovery and `reference_tests_failed` for both modes;
no status may be upgraded to oracle-verified.

**Status:** recorded; terminal root remains rejected

## Oracle evidence

The disposition was decided before oracle execution. The owner then audited
the immutable historical references in the pinned network-disabled repository
C++ sanity image. Discovery was positive and equal at 40 normal plus 40 fresh
ASan/UBSan CTests (two per root in each mode). Nineteen roots passed both
modes. `spiral-cargo-inspection` failed both of its discovered tests in both
modes, so the family receipt truthfully reports `status: fail` and that root's
remedy records `historical_docker_audit_failed`. The bounded receipt stores
failure-output hashes rather than hidden test output.

This is `historical_docker_audit`, not `locked_oracle`, and it cannot change a
rejected status. The failing reference is an additional oracle finding, while
the other 19 runtime passes remain secondary evidence beneath the earlier
benchmark rejection.

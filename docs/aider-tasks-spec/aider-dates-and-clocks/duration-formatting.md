and fresh ASan/UBSan builds, two positive discovered tests per mode, and one
compiled/rejected topic-specific substitute per root. It also builds every
hard-rule control in both modes before importing a receipt.

## Findings

### DUR-001 — shared generic evaluator replaces every advertised objective

**Severity:** major

**Scope:** all ten legacy roots

**Observed evidence:** every legacy `.meta/example.cpp` contains the same
`Task::evaluate(vector<int>, int, int, bool)` sum/flag implementation, even
though each prompt names a different API.

**Why it matters:** the reference does not implement parking billing, stage
selection, chapter partitions, independent SLA budgets, lap ranking,
conservative discharge, maintenance transitions, category aggregation,
team-air rounding, or retention-tier selection.

**Root cause:** the v1 owner rendered names and prose around one generic
reference/header/test template.

**Remedy:** replace every legacy root with a new task ID, exact API,
independent reference, and root-specific oracle.

**Verification after remedy:** the owner must report
`primary_core_objective: achieved` and each compiled false substitute must be
rejected.

**Status:** resolved and reverified by the final Docker receipt.

### DUR-002 — template-level duplicate family

**Severity:** major

**Scope:** all 45 legacy unordered pairs

**Observed evidence:** legacy references and tests differ only through
filename substitution; their normalized control flow is identical.

**Why it matters:** ten nominal roots provide one learning objective and do
not satisfy the hard diversity rule.

**Root cause:** task IDs, titles, and prompt sentences were treated as
diversity evidence.

**Remedy:** count exactly ten v2 roots only after all 45 pairs pass the exact
seven-dimension conjunctive screen and all three coherent controls are rejected.

**Verification after remedy:** focused tests independently inspect the pair
count, dimension set, every decision/hash/containment result, changed controls,
and control rejection.

**Status:** resolved and reverified after the final owner edit.

### DUR-003 — legacy evidence cannot prove current family completion

**Severity:** blocker

**Scope:** family runtime and contamination claims

**Observed evidence:** v1 has no owner-bound seven-dimension screen, coherent
controls, semantic holdout receipt, or exact-tree Docker normal/sanitizer
receipt for the replacement family.

**Why it matters:** a host-only legacy build cannot establish
`local_family_verified` for changed owner/artifact bytes.

**Root cause:** the original generator predates the mandatory remediation
evidence ladder.

**Remedy:** invalidate v1 proof, regenerate through the owner, then run the
network-disabled pinned Docker verifier after the final owner/case/test edit.

**Verification after remedy:** reopen the manifest, all remedy records, and
Docker receipt and reconcile owner, case, reference, tree, archive/mount, image,
compiler, CMake, counts, negatives, controls, and network policy.

**Status:** resolved and reverified; the current-tree receipt passes.

## Hard-rule contract

The exact seven dimensions are: public API; owned state or algorithm;
mutation/selection rules; invalid and boundary behavior; reference control
flow; deterministic oracle; topic-specific negative fixture. Decisions are
artifact-derived after comments, strings, numeric literals, and ordinary
identifiers are normalized while C++ control tokens and algorithmic words are
preserved. Every pair must pass every dimension; there is no aggregate score.

The production evaluator must reject these coherent controls against their
source root:

1. a complete domain/identifier rename;
2. a consistently changed free-boundary policy/constants control; and
3. a consistently changed latest-rather-than-earliest tie selection.

All three must change files, remain internally consistent, build and pass their
own tests in normal and sanitizer modes, and still fail the conjunctive family
rule.

## Findings that apply to all 20 tasks

### F1 — The advertised data structure is not the task being taught

Every task's editable header stores its state as `std::set<int> values_`, and
every reference implementation delegates insertion, deletion, predecessor,
ceiling, iteration, and the task-specific query to that container. The hidden
tests also use `std::set` as their behavior oracle. The so-called AVL rotation
sequences and red-black deletion cases only assert externally observable
ordered-set results; they do not inspect a tree, height, colors, links, or
balancing invariants.

As a result, a correct target answer is a thin `std::set` wrapper. It neither
requires nor demonstrates AVL rotations, red-black recoloring, node ownership,
or balanced-tree deletion. The names `avl-*` and `rb-*` therefore overstate the
curriculum's content.

**Required solution:** choose one of these honest designs before training:

1. **Balanced-tree curriculum:** replace `std::set` in the editable state and
   reference with an independently implemented AVL or red-black tree; make
   insertion/deletion cases exercise its invariants; and add a narrowly scoped
   test-only invariant/height probe or deterministic complexity-bound evidence
   that distinguishes balancing from a degenerate BST.
2. **Ordered-set API curriculum:** rename the topic and every task so they do
   not claim AVL/red-black implementation training. Keep the `std::set`
   reference, but replace the fake rotation language with domain-relevant
   behavior and do not use the set as evidence of balanced-tree uplift.

Do not merely rename a `std::set` wrapper to an AVL or red-black task.

### F2 — The 20 tasks are template variants, not independent task roots

All tasks share the same generated skeleton: a positive-integer unique ordered
set, add/remove/contains, strict predecessor, ceiling, ascending enumeration,
and exactly one small extra operation (range, rank, nearest, floor, promote, or
percentile). The domain vocabulary changes—scores, tariff breakpoints, cargo
IDs, and so on—but state, operation shape, invalid-input rules, test trace, and
reference strategy are generated from the same template.

This conflicts with the materialization guide's rule that a domain rename alone
is not a new task. It also creates severe family leakage: a model can memorize
one solution pattern and replay it across all 20 roots. That would make a
training improvement poor evidence of generalization to the official holdout.

**Required solution:** retain at most one representative task per algorithmic
contract, then redesign the remaining roots around materially different data,
operations, error modes, and edge cases. Examples include duplicate-aware
multisets, interval augmentation, key-to-payload maps, order statistics with
updates, stable iterators, split/join, range deletion, persistence, or
concurrency-free transactional batches. Each new API and test suite must be
authored independently and then screened as a task family by the primary SFT
pipeline.

### F3 — Current tests prove API behavior, not the claimed implementation

The visible and hidden tests do check useful conditions: zero rejection,
duplicate insertion, stale removal, ordering, query boundaries, a deterministic
mutation trace, and four three-item insertion orders. However, the resulting
output is identical for `std::set`, a sorted vector, or an unbalanced BST. The
“LL/RR/LR/RL” labels are not a structural proof, and the deletion checks do not
exercise red-black color cases or AVL height restoration.

**Required solution:** add task-specific adversarial cases and a valid
mechanism to verify the promised property. For AVL, expose a restricted
validation result or height bound to test code and test LL/RR/LR/RL plus
deletion rebalancing. For red-black, validate root color, red-parent rules, and
equal black height through a test-only interface. If internals deliberately
remain hidden, change the curriculum claim to behavior-only ordered indexes
and remove structure-specific wording.

### F4 — Historical release evidence is not a local remediation blocker

The historical release pipeline is out of scope for this local family. Its
missing rows, token/mask ledgers, split finalization, producer verification,
and consumer export do not block remediation. The missing local gates are the
real implementation, locked normal/sanitizer oracle receipts, and benchmark
plus duplicate-family screens.

**Required solution:** resolve F1–F3 and F5–F9, then regenerate and verify the
local family. Do not hand-convert these directories into JSONL or train on them.
Keep official Aider Polyglot roots and semantic copies outside the curriculum.

### F5 — The model-visible documentation is not a self-contained task contract

Every introduction is only a status-like sentence (“newly authored local ... diagnostic”), and every instructions file is a generated ordered-set paragraph. The original Aider specification requires visible docs to state the behavioral contract well enough that a solver need not read hidden tests or the reference. Current docs omit no-result behavior for predecessor/ceiling, public examples, and a real domain data model.

The following rules are also absent from the visible prompt: `first > last` and endpoint behavior for all range roots; empty-index/request behavior for the four nearest roots; no-eligible and atomic-removal behavior for the two promote roots; payload/update/precedence semantics for policy roots; player ownership and ranking/tie semantics for `avl-live-leaderboard`; and duplicate observations, empty/invalid percent, and the exact percentile formula for `rb-metric-percentiles`.

**Required solution:** Rewrite each retained `introduction.md` as a domain scenario and each `instructions.md` as a complete C++17 contract: types/ownership, method effects and return values, valid inputs, duplicate/absent/empty/invalid-range cases, ordering/ties, mutation rules, and at least two public examples including a boundary case. Remove local-status and unproven implementation labels from model-visible docs; retain provenance only in `.meta`. Verify from the rendered prompt that no hidden test is the sole source of public behavior.

### F6 — Private tests and test metadata overclaim what they prove

The hidden-test description promises LL/RR/LR/RL, deletion cases, and “randomized sorted-oracle mutations.” The code only applies four three-element sequences, deletes one value, and uses one deterministic 180-step `std::set` trace. It does not check AVL height, red-black colors/black height, or any property that rejects a sorted vector, degenerate BST, or the current wrapper.

**Required solution:** Replace the shared hidden-test template with independently authored tests per retained root and make `tests.toml` describe only executed coverage. AVL tests must validate rotations, deletion restoration, stored heights, and adversarial height bounds. Red-black tests must validate black root, no red-red edge, equal black height, and all deletion forms. The old `std::set` wrapper, a sorted vector, and a deliberately degenerate BST must each fail at least one private test.

### F7 — The balanced-tree generator is a copied BST template

`moonlight_balanced_search_tree_aider_tasks.py` imports `TaskSpec`, `_header`, `_starter`, `_reference`, `_test`, and `_cmake` from `moonlight_binary_search_tree_aider_tasks.py`; generated CMake files are named `binary_search_tree_curriculum`. This confirms cross-curriculum family leakage in addition to the within-family template duplication already described in F2.

**Required solution:** Give balanced trees an independent schema, API renderer, starter/reference renderer, test renderer, CMake renderer, and regression suite. Add explicit family IDs in a shared registry and semantic-family screening across balanced-tree and BST outputs. Reject imports of BST implementation/test renderers in a regression test, and ensure selected roots do not repeat an equivalent API/test contract under different nouns.

### F8 — Metadata/provenance are incomplete and one recorded path is stale

The original spec makes `config.json` the authoritative role map and requires meaningful source/attribution. Current configs have only `authors`, `blurb`, and file lists; they omit source/attribution and do not declare the private executable test source even though CMake runs it. Every provenance record points to `docs/GLM47_FLASH_AIDER_POLYGLOT_CPP_BALANCED_SEARCH_TREE_CURRICULUM.md`, but the checked-in curriculum is under `docs/aider-synthetic/aider-synthetic-dsa/`.

**Required solution:** Correct the generator `CURRICULUM` path. Record clean-room source, authoring method, license/usage terms, generator revision, family ID, and benchmark-separation decision in schema-approved config/provenance records. Declare every test source or introduce a reviewed private-test role that stays prompt-hidden. Validate all role paths as safe, relative, existing, and non-conflicting; regenerate outputs rather than hand-editing `.w8-biayn`.

### F9 — The verifier is not the required locked normal-plus-sanitizer oracle

The local `verify()` helper does not pass `Unix Makefiles` or the locked compiler, preserve receipts, require positive test discovery, compare normal/sanitizer counts, or bind grader image/compiler/CMake/Catch/sandbox identities. Generated CMake uses hand-written test mains, lacks Catch and an `EXERCISM_RUN_ALL_TESTS` full-suite contract, and uses an `ALL` custom target. A network-isolated local container run did pass the current normal and ASan/UBSan verifier for all 20 roots, but that helper emits neither discovery counts nor durable locked-grader receipts, so it is not local-family oracle proof.

**Required solution:** Use the repo-owned C++17/Catch scaffold or a reviewed equivalent. In the exact locked grader image, configure a clean normal build and a fresh ASan/UBSan build with `-G "Unix Makefiles"` and the locked compiler; separately discover and run tests, require positive equal counts, and persist redacted receipts bound to tree/reference mapping, compiler hash, image, CMake/Catch, and sandbox policy. A zero-test, stale reference map, failed reference, or sanitizer-only failure must reject the root.

### F10 — Dataset-release artifacts are an explicit non-claim

No local root is a dataset row or release. Dataset identities, token/mask ledgers, splits, producer verification, and consumer export are intentionally not part of local-family completion. Hand-converting `.meta/example.*` to JSONL remains forbidden.

**Required solution:** after F1–F9, record `local_family_verified` once regeneration, oracle evidence, and benchmark/family screening pass. The official `binary-search-tree` root and semantic copies remain evaluation-only.

## Conclusion

The 20 directories are structurally consistent local task artifacts, and the
generator's structural test passes. They are not yet valid SFT data or evidence
of benchmark uplift. Their central problem is conceptual rather than a missing
file: they currently train a repeated `std::set` wrapper while claiming a broad
AVL/red-black curriculum. The topic must be redesigned and fully admitted
before it can support a credible uplift claim.

# Deterministic Implementation Specification

This section replaces the open design choice in F1 for this curriculum. The
implementation target is **real balanced-tree implementation training**:
`avl-*` roots must use a repo-owned AVL tree and `rb-*` roots must use a
repo-owned red-black tree. No root in this directory may be renamed to an
ordered-index task or retain `std::set`, `std::map`, `std::multiset`,
`std::unordered_*`, GNU PBDS, Boost containers, or a third-party tree as its
indexed storage.

A root is implemented only when its public API, starter, reference, private
test validator, normal/sanitizer tests, metadata, and SFT evidence implement
this section exactly. A change to any rule below is a new task version and
requires regeneration plus a new primary-pipeline release subject.

## A. Common source and response contract

1. Each root has exactly two editable files, `<task-id>.h` then
   `<task-id>.cpp`, in that `files.solution` order. The assistant target is one
   complete whole-file block for each, in that order, and no prose.
2. Every public method is deterministic, does not perform I/O, does not read
   time/environment/global state, and does not throw for documented invalid
   input. `false` means rejection with no state change. `std::nullopt` means no
   result with no state change unless the method is explicitly documented as a
   removal.
3. All integer boundary comparisons are exact signed 64-bit comparisons.
   Keys and quantities listed as positive reject zero and negative values. A
   range with `first > last` returns an empty vector or `std::nullopt`, as
   stated per API, and never swaps endpoints.
4. Each AVL root owns explicit nodes with key, left/right child ownership,
   stored height, and stored subtree size when rank/select is needed. Rebalance
   after every insertion and deletion. Each RB root owns explicit nodes with
   color, parent/left/right links or equivalent sentinels, and performs standard
   insertion and deletion fix-up. The reference must be a readable independent
   implementation of the same tree type, not an answer-shaped copy of the
   starter.
5. A test-only declaration is compiled only with `CURRICULUM_TESTING`:
   `TreeCheck validate_for_test() const;`. For AVL, `TreeCheck` contains
   `bool valid`, `std::size_t nodes`, and `int height`; `valid` means ordered
   keys, unique node ownership, stored heights/sizes correct, and every child
   height difference at most one. For RB, it contains `bool valid`,
   `std::size_t nodes`, and `std::size_t black_height`; `valid` means ordered
   keys, a black root, no red-red edge, equal black height, valid parent links,
   and unique node ownership. It exposes no nodes, colors, or mutation API.
6. Private tests call `validate_for_test()` after every mutating operation.
   AVL roots must also satisfy `height <= 2 * ceil_log2(nodes + 1)` for all
   nonempty tested states. Here `ceil_log2(n)` is zero for `n <= 1`; otherwise
   it is the least nonnegative integer `k` for which `n <= 2^k`. RB roots must
   satisfy the matching valid-color and black-height checks. Test code may use
   sorted vectors as a behavior oracle, but never `std::set`/`std::map` as the
   only evidence of balancing.
7. All roots receive a deterministic 10,000-operation mutation trace generated
   from `state = state * 1664525U + 1013904223U`; operation and operands are
   derived from the successive unsigned values exactly as defined in the root
   test. The reference behavior oracle is a sorted vector or explicit simple
   record list. The private test checks public output and `TreeCheck` after each
   mutation.

## B. Exact public APIs and per-root behavior

All declarations below are in namespace `curriculum`, include only C++17
standard-library headers needed by the declaration, and use `std::string` IDs
that must be nonempty ASCII characters in `[A-Za-z0-9_-]`. Invalid IDs reject
without mutation. Vectors are returned in the stated deterministic order.

### B1. `avl-live-leaderboard`

```cpp
struct LeaderboardEntry { std::string player_id; std::int64_t score; };
class LiveLeaderboard {
 public:
  bool upsert(std::string player_id, std::int64_t score);
  bool erase(std::string_view player_id);
  std::optional<LeaderboardEntry> entry(std::string_view player_id) const;
  std::optional<std::size_t> rank_of(std::string_view player_id) const;
  std::vector<LeaderboardEntry> top(std::size_t count) const;
};
```

`score` must be positive. `upsert` inserts a new player or replaces that
player's score and returns true only when the observable entry changes. Rank is
one-based, highest score first; equal scores are ordered by ascending
`player_id`. `top(0)` is empty; otherwise it returns at most `count` entries
in rank order. Maintain an AVL index keyed by `(score, player_id)` with subtree
sizes and a separate player-to-current-key lookup. Private tests cover score
replacement across rotations, equal-score lexical ties, deletion of a
zero/one/two-child indexed node, and rank/select after each mutation.

### B2. `avl-api-rate-limits`

```cpp
struct RateLimit { std::int64_t threshold; std::int64_t max_requests; std::string rule_id; };
class ApiRateLimits {
 public:
  bool put(RateLimit rule);
  bool erase(std::int64_t threshold);
  std::optional<RateLimit> resolve(std::int64_t request_count) const;
  std::vector<RateLimit> in_window(std::int64_t first, std::int64_t last) const;
};
```

All numeric fields are positive. `threshold` is unique. `put` inserts or
replaces the complete rule at its threshold and returns false only for invalid
input or byte-for-byte identical replacement. `resolve` returns the rule with
greatest threshold not exceeding `request_count`, or nullopt. `in_window`
returns ascending thresholds inclusive, or empty when reversed. The AVL key is
threshold and the payload is the full rule. Tests cover replace, threshold
boundaries, range boundaries, and deletion rebalancing.

### B3. `avl-appointment-slots`

```cpp
struct Appointment { std::int64_t start; std::int64_t duration; std::string booking_id; };
class AppointmentSlots {
 public:
  bool reserve(Appointment appointment);
  bool cancel(std::string_view booking_id);
  std::optional<std::int64_t> next_available(std::int64_t requested_start,
                                              std::int64_t duration) const;
  std::vector<Appointment> scheduled() const;
};
```

`start` is nonnegative, `duration` positive, and booking IDs are unique. Two
appointments conflict when their half-open intervals overlap; conflicts reject.
`next_available` returns the earliest valid start at or after `requested_start`
that can host `duration`; it searches only forward gaps between scheduled
intervals and returns nullopt for invalid duration. It does not mutate. The AVL
is keyed by start and stores interval payloads; tests cover adjacent intervals,
interior gaps, cancel/reuse, and root deletion.

### B4. `avl-inventory-restock`

```cpp
struct RestockRule { std::string sku; std::int64_t reorder_at; std::int64_t target_stock; };
class InventoryRestock {
 public:
  bool put(RestockRule rule);
  bool erase(std::string_view sku);
  std::optional<RestockRule> next_rule(std::int64_t on_hand) const;
  std::vector<RestockRule> rules() const;
};
```

IDs are unique; both numeric fields are positive and `target_stock >=
reorder_at`. `next_rule` returns the rule with greatest `reorder_at <= on_hand`;
ties are ascending SKU. It returns nullopt when none applies. The AVL key is
`(reorder_at, sku)`, with a SKU lookup for replacement/deletion. Results are
ordered by increasing `reorder_at`, then SKU. Tests distinguish replacement,
ties, deletion, and no-applicable-rule behavior.

### B5. `avl-memory-free-ranges`

```cpp
struct Block { std::int64_t start; std::int64_t length; };
class MemoryFreeRanges {
 public:
  bool release(Block block);
  std::optional<Block> allocate(std::int64_t length);
  std::vector<Block> free_blocks() const;
};
```

Starts are nonnegative, lengths positive, and `start + length` must not
overflow. Free blocks are nonoverlapping and nonadjacent; `release` rejects any
overlap but merges immediately adjacent blocks. `allocate` chooses the lowest
start with length at least the request, removes it, and reinserts the remaining
tail if any. It returns nullopt for invalid/unsatisfied requests. The AVL is
keyed by start and stores block length. Tests require split, left/right/both
merge, first-fit determinism, and rotations caused by merge/delete.

### B6. `avl-coupon-thresholds`

```cpp
struct Coupon { std::int64_t minimum_spend; std::int64_t discount_cents; std::string code; };
class CouponThresholds {
 public:
  bool put(Coupon coupon);
  bool erase(std::int64_t minimum_spend);
  std::optional<Coupon> best_for(std::int64_t spend) const;
};
```

All numeric fields are positive and thresholds are unique. `best_for` returns
the coupon at the greatest threshold not exceeding spend; no coupon is returned
below the first threshold. Replacement retains no historical value. The AVL is
keyed by threshold. Tests cover exact thresholds, replacement, boundary
queries, and deletion rebalancing.

### B7. `avl-game-matchmaking`

```cpp
struct Player { std::string player_id; std::int64_t rating; };
class GameMatchmaking {
 public:
  bool join(Player player);
  bool leave(std::string_view player_id);
  std::optional<Player> closest_opponent(std::string_view player_id,
                                         std::int64_t max_delta) const;
};
```

Ratings are positive and player IDs unique. The caller is excluded from the
candidate set. Invalid/missing player or negative `max_delta` returns nullopt.
Choose the smallest absolute rating difference within `max_delta`; tie-break by
lower rating then ascending ID. The AVL key is `(rating, player_id)` with an ID
lookup. Tests cover self exclusion, equal ratings, both tie breaks, leave, and
rotations under joins.

### B8. `avl-energy-tariffs`

```cpp
struct Tariff { std::int64_t start_usage; std::int64_t cents_per_unit; std::string tariff_id; };
class EnergyTariffs {
 public:
  bool put(Tariff tariff);
  bool erase(std::int64_t start_usage);
  std::optional<Tariff> active_at(std::int64_t usage) const;
```
